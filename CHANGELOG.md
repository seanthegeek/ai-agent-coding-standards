### Added

- Slow-suite roster in the "Testing" section of `templates/AGENTS.md` — each project names its slower or network-dependent suites and the code that requires them, because the review step in `templates/CLAUDE.md` reads that list and the fresh-context review prompt is filled in from it. New here rather than ported: the ported text referred to such a list, which the project it came from has and this template did not
- Opus review loop and a single final Fable review in `templates/CLAUDE.md` — the fresh-context rounds run on Opus until a pass finds nothing beyond wording, then Fable reviews last, on the final diff, as a fresh subagent rather than in the planning session that designed the change. Supersedes the single "review with Fable" step, keeping a different model on the final diff while spending it once instead of every round. Ported from [seanthegeek/forgejo-upgrade#6](https://github.com/seanthegeek/forgejo-upgrade/pull/6)
- Loop mechanics in the "End with a fresh-context review" theme of `templates/AGENTS.md` — the bare-prompt rule (no change-specific checklist, because a checklist written by the author points the reviewer at what the author already thought of), the wording-versus-substantive threshold that decides whether another round is owed, per-reviewer scoping, the Copilot round as part of "done", and the warning that a change editing the instruction files has edited its own review, since every reviewer here reads them from the branch under review rather than the base. Scoping is per reviewer rather than per round number so that a reviewer no earlier round used reads the whole diff; scoping by round number would hand the model brought in *because* it is different nothing but the last wording fix. Ported from [seanthegeek/forgejo-upgrade#5](https://github.com/seanthegeek/forgejo-upgrade/pull/5) and [#6](https://github.com/seanthegeek/forgejo-upgrade/pull/6), apart from the instruction-files warning, which is new here
- "The fresh-context review prompt" in `templates/AGENTS.md` — the verbatim text handed to a fresh-context reviewer, the two adoption-time edits it asks for (a bracketed list of checks each project replaces with its own commands, and a note of the scratch paths and expected failures those checks produce, without which "do not change any file" forbids running them), the one substitution and one addition allowed per use, and the commit-and-fetch steps that have to precede it, since an uncommitted fix is missing from the diff the reviewer is handed while still present in the files it reads whole, and a failed fetch leaves the review running against a base that never moved. Ported from [seanthegeek/forgejo-upgrade#5](https://github.com/seanthegeek/forgejo-upgrade/pull/5) and [#6](https://github.com/seanthegeek/forgejo-upgrade/pull/6)
- "Treat outside values and pasted commands as code" review theme in `templates/AGENTS.md` — a value from outside the checkout is data until proven otherwise, including how it reaches a Makefile recipe or a CI `run:` step and the hostile-value test it owes; and a command in the README or the docs is reviewed as code, because someone pastes it into a real shell. Ported from [seanthegeek/forgejo-upgrade#5](https://github.com/seanthegeek/forgejo-upgrade/pull/5)
- "Review discipline" section in `templates/AGENTS.md` — six themes distilled from real multi-agent review cycles: review prose as prose, nothing is pre-verified, check claims against what they range over, verify what CI enforces, treat outside values and pasted commands as code, and end with a fresh-context review
- "Testing" section in `templates/AGENTS.md` — both halves of exclusive-claim tests, regression tests proven against the unfixed code, and confirming end-to-end runs execute the edited code — plus two additions to the "Check claims against what they range over" review theme (state updates ordered after the fallible action they track; equal handling of return-value and exception failure paths), distilled from [domainaware/parsedmarc#863](https://github.com/domainaware/parsedmarc/pull/863). Restructures the "Testing and review" section that landed in [#2](https://github.com/seanthegeek/ai-agent-coding-standards/pull/2), whose fresh-context-review rule is superseded by the fuller "End with a fresh-context review" theme
- Conditional implementer model in `templates/CLAUDE.md` — Sonnet by default, Opus for large multi-file work or subtle/paired-protocol changes, decided at planning time
- `templates/AGENTS.md` — shared conventions for AI agents working on Sean's projects
- `templates/CLAUDE.md` — Claude Code wrapper that includes `AGENTS.md`
- `README.md` — overview and usage instructions
- `LICENSE` — MIT
- `.vscode/settings.json` — cSpell dictionary for project-specific terms
